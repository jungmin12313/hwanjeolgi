# 환절기 편집국 (Claude 운영판)

> 기획 회의부터 발행까지 이어지는 작은 편집국.
> 에이전트가 많이 일하는 것보다, **잘못된 결과물이 다음 단계로 넘어가지 못하게 만드는 것**이 목적이다.

모든 역할은 `BRAND_TONE.md` · `EDITORIAL_WORKFLOW.md` · `EDITORIAL_CHECKLIST.md`를 최상위 규칙으로 따른다.

---

## 1. 조직도

| 역할 | 누가 | 하는 일 | 통과 기준 |
|---|---|---|---|
| **발행인** | 편집장(사람) | 기획 승인, 최종 게시 승인 | 두 번만 개입한다 |
| **데스크** | Claude 본 세션 | 단계 배정, 반려·재작업 지시, 산출물 보관 | 각 단계 산출물이 파일로 남아야 다음 단계로 |
| ① 기획자 | 서브 에이전트 | 서로 다른 관점의 기획안 2~3개 | 워크플로 부록 A-1 양식 |
| ② 기획 심사위원 | **독립** 서브 에이전트 | 5항목 심사, 반려·대안 | 5항목 중 하나라도 미달이면 반려 |
| ③ 리서처 | 서브 에이전트 | 1차 출처 추적, 취재표 작성 | 모든 사실에 출처·날짜·원문/재인용 구분 |
| ④ 팩트체커 | **독립** 서브 에이전트 | 취재표·초고의 인용·수치·날짜 재대조 | 대조 불가 항목은 본문에서 제외 |
| ⑤ 집필자 | 서브 에이전트 | 핵심 관점·구성안·초고 | 구성안 승인 후에만 집필 |
| ⑥ 비평 에디터 | **독립** 서브 에이전트 | 상투성·논리 비약·설명 과잉 공격 | 100점 심사, 90점 미만 반려 |
| ⑦ 제작 매니저 | `desk/render.py` | final.json → PNG, 넘침·미확정 표기 검사 | 검수보고서 "발행본" + 90점 이상일 때만 렌더 |

**독립**이라고 표시한 역할은 집필 과정을 보지 않은 새 에이전트로 부른다. 쓴 사람이 자기 글을 심사하지 않는다.

### 9개 역할 안에서 합친 것과 뺀 것
- **구성 편집자 + 집필자 → ⑤ 집필자.** 구성안을 따로 파일로 남기고 데스크가 승인하는 게이트로 대신한다. 같은 사람이 설계와 집필을 해도, 설계가 승인 전에는 쓰지 않는다.
- **아트 디렉터 → 뺐다.** 환절기 디자인은 `index.html` 도구에 고정돼 있다(흰 배경, 동해독도, 계절색 규칙). 매 편 새로 디자인하지 않는 게 브랜드다. 디자인 변경은 도구 버전업으로만 한다.
- **Canva → 쓰지 않는다.** 자체 디자인 엔진(도구)이 이미 1080×1350 PNG를 만든다.

## 2. 흐름과 게이트

```
[발행인] 키워드
   ↓
① 기획자 → 기획안 2~3개 ─→ ② 심사위원(독립) ─ 반려 → ①
   ↓ 통과
[발행인 승인 ①] ──────────── 사람 개입 1
   ↓
③ 리서처 → 02_취재표.md ─→ ④ 팩트체커(독립) ─ 대조 실패 → ③ 또는 기획 수정
   ↓
⑤ 집필자 → 03_구성안.md ─→ 데스크 ─ 관점이 자료로 안 받쳐지면 → ①
   ↓
⑤ 집필자 → 04_초고.md ─→ ⑥ 비평 에디터(독립) ─ 90점 미만 → ⑤ (필요하면 ③·①)
   ↓                    └→ ④ 팩트체커 재검증
05_검수보고서.md (판정: 발행본)
   ↓
⑦ render.py → png/ + caption.txt
   ↓
[발행인 승인 ②] → 게시 ──── 사람 개입 2
```

- 게이트를 통과하지 못하면 **이전 단계로 돌아간다.** 문장만 고치거나 결말을 감성적으로 덮지 않는다.
- 발행인이 개입하는 곳은 **기획 승인**과 **게시 승인** 두 곳뿐이다. 나머지 품질 관리는 데스크의 일이다.

---

## 3. 프로젝트 폴더

편마다 `desk/projects/YYYY-MM-DD_슬러그/`에 아래 파일이 남는다. `_template/`을 복사해서 시작한다.

| 파일 | 만드는 역할 |
|---|---|
| `01_기획안.md` | ① 기획자 + ② 심사 결과 |
| `02_취재표.md` | ③ 리서처 + ④ 팩트체커 대조 결과 |
| `03_구성안.md` | ⑤ 집필자 (데스크 승인 표시) |
| `04_초고.md` | ⑤ 집필자 (수정 이력 포함) |
| `05_검수보고서.md` | ⑥ 비평 에디터 + ④ 팩트체커 |
| `final.json` | 데스크 (도구 불러오기 형식) |
| `caption.txt` | 데스크 |
| `png/` | ⑦ render.py |
| `06_발행기록.md` | 게시 일시, 채널, 승인자 |

---

## 4. 제작 매니저 — render.py

```bash
python3 desk/render.py desk/projects/2026-11-26_슬러그
```

- `05_검수보고서.md`에 `판정: 발행본`과 `합계: 90` 이상이 없으면 **렌더하지 않는다.**
- `final.json` 안에 `[`로 시작하는 빈칸, `확인할 것`, `TODO`가 남아 있으면 **렌더하지 않는다.**
- 렌더 후 글 넘침(⚠) 장이 있으면 실패로 보고한다.
- 결과: `png/00_표지.png …`, `png/환절기_슬러그.zip`
- `--draft`를 붙이면 게이트를 건너뛰고 `png_draft/`에 시안으로만 뽑는다. 시안은 게시하지 않는다.

## 5. 현황판

- 주소: https://hwanjeolgimagazine.netlify.app/desk/
- 편마다 8단계 진행 막대, 상태·심사 점수, 막힌 이유, 다음 할 일, 발행인 확인 필요 표시.
- 편을 누르면 상태·기획안·취재표·구성안·초고·검수보고서·캡션·발행기록·PNG를 탭으로 바로 볼 수 있다.
- 데스크는 단계가 끝날 때마다 `00_상태.md` 수정 → `build_status.py` → 푸시한다.

## 6. 게시

- **1단계(지금):** PNG와 캡션까지 자동. 게시는 발행인이 승인 후 직접 올린다.
- **2단계:** Metricool 커넥터를 연결하면 승인 후 예약 게시까지 데스크가 처리한다. 게시물은 승인 없이 올라가지 않는다.
- 완전 자동 게시는 하지 않는다. 잘못된 인용이나 사진 권리 문제는 자동으로 책임질 수 없다.
